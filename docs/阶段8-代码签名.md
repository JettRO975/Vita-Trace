# Vita Trace — 代码签名

> 状态：签名流水线已实现并用自签名证书验证；**还没有可公开分发的 CA 证书**。
> 自签名只能验证“签名/时间戳机制能跑通”，不能消除 SmartScreen 的“未知发布者”。

---

## 1. 为什么需要代码签名

Windows 对下载的 exe 会检查 Authenticode 签名：

- 未签名：SmartScreen 可能提示“Windows 已保护你的电脑”，发布者显示“未知”。
- 自签名：有签名，但证书链不被信任，仍然提示“未知发布者”。
- CA 签发的代码签名证书：发布者显示组织/个人名称；OV 证书需要积累信誉，EV 证书通常更快建立信誉。
- 签名只保护 **exe/dll**，不保护 zip；zip 的完整性用 `.sha256` 校验。

---

## 2. 当前机器的事实

- 机器上没有 CA 代码签名证书；验证用的自签名测试证书已在验证后删除，仓库不包含任何证书或私钥。
- Windows SDK 自带 `signtool.exe`：
  `C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe`
- 自签名验证结果（历史）：`Get-AuthenticodeSignature` 返回 `UnknownError`，原因是根证书不受信任——这是自签名的预期结果。
- 测试签名包只用于本地验证，已从仓库目录移出，不随源码分发。

## 3. 签名流水线

### 3.1 先生成未签名包

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1
```

得到：

```text
dist\VitaTrace-0.7.0-win-x64\
├─ VitaTrace.exe
├─ README.md
├─ install.ps1
└─ uninstall.ps1
dist\VitaTrace-0.7.0-win-x64.zip
```

### 3.2 用证书签名并重新打包

已有 PFX：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sign-package.ps1 `
  -Version 0.7.0 `
  -PfxPath "D:\certs\vita-trace.pfx" `
  -PfxPassword "***"
```

证书已安装到当前用户证书库（推荐，私钥不落地到命令行）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sign-package.ps1 `
  -Version 0.7.0 `
  -Thumbprint "ABCDEF..."
```

脚本会：

1. 调用 `sign.ps1` 对 `VitaTrace.exe` 执行 `signtool sign /fd SHA256`。
2. 默认加 DigiCert RFC3161 时间戳（`/tr http://timestamp.digicert.com /td SHA256`）。
3. 用 `Get-AuthenticodeSignature` 检查签名存在。
4. 重新生成 zip 与 `.sha256`。

只签一个文件：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sign.ps1 `
  -ExePath ".\dist\VitaTrace-0.7.0-win-x64\VitaTrace.exe" `
  -Thumbprint "ABCDEF..."
```

### 3.3 验证

```powershell
Get-AuthenticodeSignature ".\dist\VitaTrace-0.7.0-win-x64\VitaTrace.exe" |
  Format-List Status, StatusMessage, SignerCertificate, TimeStamperCertificate

& "C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe" `
  verify /pa /v ".\dist\VitaTrace-0.7.0-win-x64\VitaTrace.exe"
```

预期：

- CA 证书：`Status = Valid`，`signtool verify` 成功。
- 自签名：`Status = UnknownError`，`signtool verify` 因根不受信任失败；这是测试证书的正常结果。

## 4. 选哪种证书

| 方案 | 成本/门槛 | SmartScreen | 适合 |
| --- | --- | --- | --- |
| 自签名 | 免费 | 仍提示未知发布者 | 只验证签名机制、内部测试 |
| OV 代码签名 | 每年付费；需身份/组织验证 | 逐步建立信誉，初期仍可能提示 | 个人/小团队正式发布 |
| EV 代码签名 | 更贵；硬件令牌/HSM | 通常更快获得信誉 | 商业分发、希望减少提示 |
| Azure Trusted Signing | Azure 订阅 + 身份验证；云端签名 | 取决于 Microsoft 信誉体系 | 不想管理硬件令牌的团队 |
| 学校/公司内部 CA | 免费（受限） | 仅在该组织信任的机器上有效 | 校园/企业内部 |

**不能承诺“签名后一定没有 SmartScreen 提示”。** 新证书需要信誉积累；EV/受信任签名通常更快，但不是绝对。

## 5. 安全注意事项

1. **不要把 PFX、密码、私钥提交到 Git**；`.gitignore` 已忽略 `*.pfx`、`*.p12`、`*.snk`、`secrets/`。
2. 优先把证书安装到证书库（`Cert:\CurrentUser\My`）后用 `-Thumbprint`，避免密码出现在命令历史。
3. 生产签名建议使用 HSM/EV 令牌或 Azure Trusted Signing；不要把私钥放在普通开发机。
4. 签名后重新计算 zip 的 SHA256，并更新发布说明；签名 exe 的哈希会变化。
5. 自签名测试证书用完可以删除：

```powershell
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert |
  Where-Object { $_.Subject -eq 'CN=Vita Trace Test Signing' } |
  Remove-Item
```

需要重新做自签名测试时，可再创建一张（不要用于对外发布）：

```powershell
New-SelfSignedCertificate -Type CodeSigningCert `
  -Subject 'CN=Vita Trace Test Signing' `
  -CertStoreLocation 'Cert:\CurrentUser\My' `
  -KeyExportPolicy NonExportable -KeyLength 3072 -HashAlgorithm SHA256 `
  -NotAfter (Get-Date).AddYears(1)
```

## 6. 当前结论

- 签名脚本和自签名验证已完成；**正式包仍是未签名状态**，因为机器上没有 CA 证书。
- 自签名测试包只用于验证签名/时间戳和安装流程，已清理，不是可公开分发的发布包。
- 下一步需要确定证书来源：
  1. 已有 PFX / 证书指纹 → 直接运行 `sign-package.ps1`。
  2. 购买 OV/EV → 先完成 CA 身份验证，拿到 PFX/令牌。
  3. Azure Trusted Signing → 开通服务并完成身份验证，再接入 `signtool`/dlib。
- 在拿到正式证书前，不应把自签名包对外分发；自签名不会让 SmartScreen 显示可信发布者。
