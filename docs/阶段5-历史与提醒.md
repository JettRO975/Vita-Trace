# Vita Trace — 第五阶段：历史记录、刷新与低电量提醒

> 状态：已完成并构建通过；本阶段只针对当前两款已适配设备（雷柏 VT7 Max、迈从 G98 Pro）做真实数据验收。
> 目标不是增加新品牌，而是让已经能读到的电量“留得下来、看得见、低电量能提醒”。

实际界面（雷柏 69% + 迈从键盘 100%，键盘曲线来自 `history.json` 的历史加载）：

![第五阶段主界面](images/main-keyboard.png)

## 1. 本阶段完成内容

1. **历史持久化**：真实电量采样写入本机 JSON 文件，应用重启后自动加载。
2. **采样策略**：电量变化才采点；电量不变时最多每 10 分钟补一个点，避免 90 天历史被噪音撑满。
3. **90 天保留**：按 `HistoryRetentionDays` 清理旧采样，每小时最多清理一次。
4. **曲线复用**：主界面圆环右侧曲线读取持久化历史；加载时只取最近 60 个点用于绘制。
5. **多设备低电量提醒**：每台设备单独记录“已提醒”状态；设备恢复后再次跌破阈值会重新提醒。
6. **刷新与托盘保持**：默认 60 秒、可设 15–3600 秒；关闭窗口进托盘、低电量气泡 + 图标红色叠加 + 窗口可见时闪任务栏。

---

## 2. 为什么用 JSON 而不是 SQLite

原计划使用 SQLite，但当前开发机无法联网获取 NuGet 包，项目又刻意保持**零第三方依赖**。历史数据规模很小：

- 每台设备每天最多约 144 个点（10 分钟一个）；
- 90 天约 1.3 万点/设备；
- 当前只支持 2 台设备。

JSON 文件完全可以承载，而且：

- 不需要原生 SQLite DLL，绿色版复制即可运行；
- 用户可以直接备份/查看；
- 写入采用“临时文件 + 原子替换”，不会留下半个文件。

如果后续设备数或采样频率显著增加，可以在 `IHistoryStore` 后面替换成 SQLite，界面层不需要改。

## 3. 文件格式

路径：

```text
%LOCALAPPDATA%\VitaTrace\history.json
```

结构：

```json
{
  "Version": 1,
  "Devices": {
    "hid:ce740f5b1e3ffb55": [
      { "Timestamp": "2026-10-20T21:15:02.2216738+08:00", "Percent": 69 }
    ],
    "receiver:114fd5401f421a83": [
      { "Timestamp": "2026-10-20T21:15:02.2799674+08:00", "Percent": 100 }
    ]
  }
}
```

- `Devices` 的 key 是设备稳定 ID，不是显示名称；用户改别名不会丢历史。
- `Percent` 为 `null` 的采样点预留给断开/读取失败，当前阶段只写入成功读数。
- 文件损坏时重命名为 `history.json.corrupt-<时间>`，应用从空历史启动，不阻塞主流程。

## 4. 采样与加载流程

```text
刷新
  ↓
枚举设备
  ↓
读取器链（WindowsPnp → Rapoo → MCHOSE 键盘 → CompX → MCHOSE 鼠标）
  ↓
得到 Ok 读数
  ↓
DeviceItemViewModel.AddHistory
  ├─ 与上一点比较：电量相同且 <10 分钟 → 丢弃
  ├─ 加入界面集合（最多 60 点）
  └─ IHistoryStore.Append → history.json
  ↓
下次启动
  ↓
MergeDevices 创建新卡片时 LoadHistory
  ├─ 读取 since = now - HistoryRetentionDays
  └─ 取最近 60 点画曲线
```

关键约束：

- **只有 `BatteryStatus.Ok` 才写历史**。`Stale` 是旧时间戳，再写会造成时间倒序。
- 演示模式使用 `NullHistoryStore`，不会污染真实历史文件。
- 历史读取失败只记日志，不影响设备枚举和电量读取。

## 5. 低电量提醒

- 阈值来自设置，默认 20%，范围 5–50%。
- 判定条件：有有效百分比、设备在线、不是接收器、百分比低于阈值。
- 每台设备用设备 ID 记录是否已提醒：
  - 第一次跌破阈值 → 气泡 + 托盘图标红色叠加 + 窗口可见时 `FlashWindowEx`；
  - 仍低于阈值 → 不重复刷屏；
  - 恢复后再次跌破 → 重新提醒。
- 托盘模式下没有任务栏按钮，因此不能只依赖“任务栏图标闪动”。

## 6.1 界面细节修正（本轮）

- 刷新按钮的矢量图标改为单一 `Path`，圆角端点、旋转中心在按钮中心，避免此前后台白色方块与“斜着转”的观感。
- 增加全局 `ToolTip` 样式：深色主题下使用深色背景 + 主文字色，浅色主题下使用卡片色 + 深色文字，解决“悬停有提示框但文字看不见”。
- 设备详情不再显示 `\\?\hid#...` 设备路径；路径仍写入日志，排查时可用。
- 托盘图标在窗口显示后调用一次 `Reassert()`，应对 Explorer/开机自启时首次 `Shell_NotifyIcon` 被系统丢掉；单击图标打开窗口，关闭时首次气泡提示“图标在 ^ 溢出区”。
- 托盘相关限制：Windows 11 默认把新图标收进 `^`，需要在“设置 → 个性化 → 任务栏 → 其他系统托盘图标”中打开 Vita Trace；这是系统行为，不是应用未启动。
- 单实例恢复：已有实例隐藏在托盘时，再次启动不会再只弹“已在运行”，而是通过 `EnumWindows` 找到旧主窗口，给它发送私有消息 `WM_APP+1`；第一个实例收到后在 WPF Dispatcher 里执行 `Show()`。不能从第二个进程直接 `ShowWindow`，那样只显示 Win32 外框，WPF 仍认为窗口是 Hidden，内容区会黑屏。

## 6.2 多设备托盘与重命名（第五阶段增量）

- 三处显示分工：任务栏大图标 = V 应用图标；`^` 溢出区 = V 应用图标的缩小版；`^` 旁边 = 每台可读设备的电量圆环（编号 + 弧度）。Windows 一个托盘图标只能处于“溢出区”或“固定显示”之一，所以应用图标保持 `IsPromoted=0`，设备圆环设 `IsPromoted=1`。
- 圆环实际效果（任务栏按钮图标由 24px 放大）：`images/tray-ring.png` 显示空心环、中心序号和 69% 的闭合弧度。
- 托盘从“一个应用图标”改为“应用图标 + 每台可读设备一个圆环”：
  - 图标为 32×32 圆，圈内显示设备在界面中的序号；
  - 电量 ≥20% 绿色，<20% 红色；
  - 悬停 Tooltip 显示“序号. 名称 — 电量”；
  - 单击打开并选中对应设备；右键菜单只保留“刷新 / 退出”，打开窗口直接单击图标。
- 只为 `IsTrayVisible` 的设备建图标：已连接、非接收器、`BatteryStatus.Ok`、百分比在 0–100。不支持、读取失败、接收器、有线、断开都不生成图标。
- 界面左侧每张设备卡增加序号徽标；序号按列表从上到下 1..N，未读到的设备也占一个号，因此托盘号码可能不连续（例如 1、2、3、5），但和界面一致。
- 标题右侧铅笔按钮进入内联重命名：Enter 保存、Esc 取消，留空恢复系统名称；别名写入 `settings.json` 的 `Aliases`，重启后保留。
- 隐藏窗口恢复改为给第一个实例发 `WM_APP+1`，由 WPF 自己 `Show()`；避免第二个进程直接 `ShowWindow` 造成“有外框、内容黑屏”。

## 7. 当前限制

- 历史曲线最多显示最近 60 个点，完整 90 天数据仍在文件里；后续可加“导出/缩放”。
- 雷柏鼠标休眠时不推送状态帧，界面会显示“读取失败”；移动鼠标后刷新恢复。
- 迈从键盘的 `0x13/0x4A` 帧里充电字节语义未公开，本阶段只显示电量，不显示“正在充电”。
- 当前只支持雷柏 VT7 Max 与迈从 G98 Pro；其他设备仍按“不支持/读取失败”显示，不伪造。
