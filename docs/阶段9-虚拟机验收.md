# Vita Trace — 虚拟机验收指南

> 结论先行：当前这台开发机**没有可直接使用的虚拟机环境**，也没有 Windows 安装 ISO。
> 因此本文给出可执行的验收路线、检查表和自动化脚本，但没有声称“已经在虚拟机里验收通过”。
> 真机 USB / 蓝牙电量仍应以物理机为准；虚拟机只适合做干净环境、安装/卸载和 UI 验收。

## 2. 推荐路线

### 路线 A：Windows Sandbox（最快，推荐做“干净环境”验收）

适合：

- 验证自包含单文件 exe 在没有安装 .NET 的干净系统中能启动。
- 验证绿色版、按用户安装/卸载、托盘、主题、语言、演示模式。
- 验证 zip 完整性和 SHA256。

不适合：

- USB 接收器 / 蓝牙设备的真实枚举与电量读取（Sandbox 不支持 USB 直通）。
- SmartScreen 的完整复现（本地复制文件通常没有“来自 Internet”标记）。

启用（管理员 PowerShell，执行后重启）：

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All
```

重启后双击 `packaging\VitaTrace.wsb`。它会把发布目录和验收脚本只读映射进沙箱：

```text
C:\VitaTrace       -> dist\VitaTrace-0.7.0-win-x64
C:\VitaTraceTests  -> tests\acceptance
```

### 路线 B：VMware Workstation Player / VirtualBox（需要 USB 直通）

适合：

- 在虚拟机里挂载 USB 2.4G 接收器，验证真实 HID 枚举、电量读取、热插拔。
- 验证蓝牙 USB 适配器（如果虚拟机软件支持直通）。

需要额外准备：

1. Windows 10 22H2 或 Windows 11 安装 ISO（当前机器没有）。
2. VMware Workstation Player 或 VirtualBox 安装包（当前机器没有）。
3. 虚拟机关机后添加 USB 控制器，运行时把接收器“连接到虚拟机”，而不是主机。

限制：

- 某些 2.4G 接收器在虚拟机中只暴露部分 HID 集合，电量协议可能读不到；这不能直接判定为应用 bug，必须回到物理机复核。
- 蓝牙适配器直通在部分虚拟机版本中不稳定；BLE 电量建议物理机测试。

### 路线 C：Hyper-V（系统自带，但无原生 USB 直通）

适合：

- 干净系统启动、安装/卸载、托盘/UI 冒烟。

不适合：

- USB HID 电量、蓝牙电量。Hyper-V 没有把任意 USB 设备直通给子机的原生功能；增强会话只重定向键鼠输入，不是完整 HID 设备。

启用（管理员 PowerShell，执行后重启）：

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All -All
```

创建 VM 需要 ISO；当前机器没有，因此本机暂时无法直接完成这一步。

## 4. 自动化冒烟测试

脚本：`tests\acceptance\Invoke-VitaTraceSmoke.ps1`

在虚拟机内运行（路径按实际解压位置调整）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File C:\VitaTraceTests\Invoke-VitaTraceSmoke.ps1 `
  -ExePath C:\VitaTrace\VitaTrace.exe `
  -Mode demo
```

真实模式：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File C:\VitaTraceTests\Invoke-VitaTraceSmoke.ps1 `
  -ExePath C:\VitaTrace\VitaTrace.exe `
  -Mode real -TimeoutSeconds 30
```

脚本会检查：

- 进程能启动；
- 主窗口标题为 `Vita Trace`；
- 日志文件存在且没有 `[ERROR]`；
- 演示模式不生成真实 `history.json`；
- 第二个实例会自行退出，不会叠出第二个窗口。

预期最后一行：

```text
RESULT: PASS
```

脚本会在 `%TEMP%\VitaTrace-Acceptance` 下创建临时数据，结束后删除；加 `-KeepData` 可保留现场。

## 6. 关于低电量与蓝牙

- 低电量：演示模式的 G304 固定 19%，可用于验证横幅和托盘图标；真实设备需要放电到阈值以下，或用厂商软件查看真实电量后对照。
- 蓝牙：虚拟机通常没有蓝牙适配器。需要 USB 蓝牙直通；即使直通，Windows PnP 电量缓存也可能滞后或卡 100%，必须与厂商软件/物理机对照。
- 不得为了“让测试通过”修改代码生成假电量；读不到就记录为限制。

---

## 7. 签名的验收

- 未签名包：`Get-AuthenticodeSignature` 为 `NotSigned`，SmartScreen 可能提示未知发布者。
- 自签名测试包：签名存在，但状态为 `UnknownError`（根证书不受信任）；SmartScreen 仍会提示，不可作为正式发布依据。
- 正式 CA 签名后：`Status = Valid`，`signtool verify /pa /v` 成功；仍需在干净 VM 中验证安装和启动。

## 9. 本机当前能做什么、不能做什么

能立即做：

- 在宿主机运行 `Invoke-VitaTraceSmoke.ps1`（已验证 demo/real 两种模式 PASS）。
- 检查 zip 哈希、exe 签名状态、安装/卸载脚本语法。
- 准备 `.wsb` 和检查表。

需要用户/管理员操作：

- 启用 Windows Sandbox 或 Hyper-V（提权 + 重启）。
- 提供 Windows ISO 和虚拟机软件（VMware/VirtualBox）。
- 直通 USB 接收器/蓝牙适配器。

因此，本机目前**不能诚实地宣称已完成虚拟机验收**；可以先完成宿主机的自动化冒烟，再按上面的路线 A/B 做干净环境与硬件验收。
