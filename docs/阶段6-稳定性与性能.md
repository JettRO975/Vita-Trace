# Vita Trace — 第六阶段：稳定性、性能与兼容性

> 状态：第一增量已完成并构建通过。
> 本阶段不新增品牌、不改界面结构，重点处理“读不到/读得慢/异常/长期运行”的问题。

---

## 1. 本阶段目标

1. 单次刷新不能被一个休眠设备拖住整个界面。
2. 读取失败时不能把旧值伪装成实时值，也不能因为一次超时就丢掉有效历史。
3. 异常必须留下可排查的日志，日志不能无限增长。
4. 在 100% / 150% DPI、Win10/Win11、浅色/深色下不出现布局错乱。
5. 托盘、热插拔、设置保存等边界路径有明确降级行为。

---

## 2. 本增量已实现

### 2.1 单个读取器 6 秒超时

`src/VitaTrace.App/ViewModels/MainViewModel.cs`：

- `ReadWithTimeoutAsync(reader, device, TimeSpan.FromSeconds(6))`
- 用 `Task.WhenAny(readTask, Task.Delay(timeout))` 限制等待时间。
- 超时返回 `BatteryReading.ReadFailed("读取超时（6 秒）")`，继续尝试下一个读取器或标记失败。
- 底层 HID `ReadFile` 仍可能继续阻塞后台线程；这是当前 Win32 同步 API 的限制，但不再阻塞界面刷新流程。

### 2.2 旧读数降级为 Stale

`src/VitaTrace.Core/Models/BatteryReading.cs`：

```csharp
public BatteryReading AsStale(string detail) => this with
{
    Status = BatteryStatus.Stale,
    Detail = detail,
    Confidence = BatteryConfidence.Medium
};
```

`MainViewModel.ReadBatteriesAsync`：

- 本轮没读到新值；
- 设备 10 分钟内有过 `Ok` / `Stale` 的有效读数；
- 保留旧百分比，状态标 `Stale`，说明“本轮未读到新值，显示上次成功读数”。

历史曲线只写 `Ok`，因此 Stale 不会制造重复点或时间倒序。

### 2.3 慢刷新日志

- `Stopwatch` 包住一次刷新。
- 超过 1500 ms 才写 `刷新耗时 ... ms，设备 ... 个`，避免每分钟刷日志。
- 读取异常仍按 `读取电量失败：设备 / reader.Id` 写 Error。

### 2.4 日志与异常（已有能力复核）

- `FileLogger` 按 `yyyy-MM-dd HH:mm:ss.fff [LEVEL]` 写入，2 MB 滚动 `.1`。
- 启动、枚举、协议读取、设置保存、托盘同步都有 INFO/WARN 记录。
- `DispatcherUnhandledException` 记录并提示；`AppDomain.UnhandledException` 记录。
- 设置加载失败会回退默认值并记录原因。

## 3. 验证步骤

1. 启动真实模式，确认设备正常显示电量。
2. 让雷柏鼠标休眠（约 1–2 分钟不移动），点“立即刷新”：
   - 6 秒内界面不冻结；
   - 若 10 分钟内有过 69%，显示“69% / 上次读数”而不是“读取失败”；
   - 移动鼠标后再刷新，恢复“正常”。
3. 查看日志：
   - 无重复刷屏；
   - 出现 `刷新耗时 ...`（如果确实慢）；
   - 无未处理异常。
4. 切换 100% / 150% DPI，检查主窗口和设置窗口不裁切。
5. 反复关闭/打开托盘、重启 Explorer，确认图标重新注册。
